# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

### Prerequisites

- **Python 3** — required for `npm start` (uses `python3 -m http.server`, falling back to `python` on Windows, where the python.org installer ships no `python3.exe`)
- **Node.js >= 18** — required for tests (`node:test`, `structuredClone`)
- Run `npm install` before first use to install Playwright dev dependency

### Development

```bash
npm start          # Start Python HTTP server at http://localhost:3000 (runs cache-bust first)
npm run cache-bust # Update ?v=<hash> of every js/css in index.html (also runs before start/test)
```

### Testing

```bash
npm test                   # Lint + unit (node:test, <1s) + E2E smoke
npm run lint               # ESLint: no-undef, no-dupe-class-members, no-unused-vars
npm run test:unit          # Only unit tests — run these after any game-rule or js/data change
npm run test:e2e           # Only Playwright E2E (headless)
npm run test:headed        # Run tests with visible browser
npm run test:ui            # Open Playwright interactive UI
npm run test:debug         # Debug mode with step-through
npm run test:report        # View HTML test report
npm run install-playwright # Install Playwright browsers (first-time setup; only chromium is used)
npm run screenshots        # Photo of every visible building alone → screenshots/buildings/*.png + index.html
npm run screenshots -- water_pump city_hall --out screenshots/antes   # only these ids, custom folder
```

**Visual check (`scripts/screenshot-buildings.js`)**: tests prove a building gets a mesh, not that it looks right. After touching meshes/materials/camera, shoot before and after (`--out`) and compare the PNGs. It uses `localhost:3000` (starts `npm start` if nothing is listening), hides HUD/labels/completion effects, disables game over (all buildings together kill the city) and exits 1 on a missing photo or `console.error`. **Anything 3D (Babylon) → load the `babylon` skill (`.claude/skills/babylon/SKILL.md`)**: mesh pipeline, rules, known visual bugs, version upgrade, Context7 id.

**Unit tests** (`tests/unit/*.test.js`, no deps): `tests/unit/load.js` loads the game's global scripts into a `vm` context with stubbed `window`/`localStorage`/silenced `console`, and returns an evaluator (`g('ResourceManager')`) because top-level `class`/`const` are lexical, not properties of `window`. Only code without Babylon/DOM is testable this way: `ResourceManager`, `LoanManager`, `EventSystem`, `SaveSystem`, `StudySystem`, `js/data/`, and `QuestSystem`'s rules (`quests.test.js` stubs `updateQuestUI`/`playMissionCompletionAudio` on the prototype, since those live in DOM partials). Objects from the `vm` realm have other prototypes — compare via `JSON.stringify`, not `deepStrictEqual`. `data.test.js` is strict: every mission reference must exist, every building `size` is an integer (the grid only occupies squares), and every objective must use a type/target listed in `SUPPORTED` — the types `QuestSystem.checkObjectiveProgress` actually measures (`build`, `resource`, `sustained`, `survival`, `avoid:water_shortage`). Adding a new objective type = implement it in `checkObjectiveProgress` **and** add it to `SUPPORTED`. In 10/2026, 9 missions were deleted because they used unimplemented types or nonexistent buildings. It also forbids a nested `effects: {}` in a building (9 green/monitoring buildings had all their effects there and did nothing — `applyBuildingEffects` only reads top-level fields) and `rewards.unlock` in missions (use `recommendStudy`).

**Unit — `tests/unit/economy.test.js` / `events.test.js`:** building income survives the per-second tax recalculation, building satisfaction (cap + diminishing returns), green buildings change pollution/storage and cost maintenance, nature-based ones work without a road (`needsRoad: false`), old saves rebuild `buildingIncome`/`buildingSatisfaction`; each event does what its text says and its end undoes its start (drought halves production, leak, campaign, population boom, equipment failure repaired at the end, industrial pollution raises treatment cost).

**E2E — `tests/partials.spec.js`:** exercises every partial (mixin) file at least once — mission UI, loans, resource panels, selection/placement overlay, camera guard, diagnostics, study book, mobile panels/touch (mobile project only) — plus a finished construction and the post-build energy alert (must say `apenas 0% de eficiência`). **When you add a partial file, add a call to it here.**

**Starting a game in E2E: `startGame(page)` from `tests/helpers.js`** — seeds a test profile in localStorage, clicks its `.profile-card` and waits for `gameManager.initialized`. It also mocks the external APIs (Open-Meteo forecast/geocoding, IBGE cities) with `page.route`, so tests never hit the network (the smoke fails on any failed request). `#btn-new-game` now opens the profile form, not the game. Every E2E test that isn't about the tutorial must call `gameManager.tutorialSystem.complete()` right after `startGame` — otherwise the game stays frozen and constructions never finish. `complete()` also **autosaves**, so after a `page.goto` in the same test the profile card opens "Continuar / Novo jogo" instead of starting (see `tests/save.spec.js`).

**E2E — `tests/player.spec.js`:** profile form (validation, IBGE city list, age → difficulty, `{nome}` in texts, saved profile listed on the menu), **pause really freezes** (`gameTime` and an ongoing construction don't move in the pause/profile screen, a popup, or a quick lesson), Esc/button cancel build mode and Esc with nothing open pauses, the `beforeunload` warning on reload mid-game, and the missions tutorial advancing on click (incl. a goal click jumping to the building).

**Unit — `tests/unit/save.test.js`:** save envelope (version, corrupt/old/other-profile saves → `reason`, never throws), one save per profile (delete one keeps the other, legacy global keys purged), and the `getSaveData` → JSON → `loadData` round trip of ResourceManager (no `history` in the save), `BuildingSystem.serializeBuilding` + `restoreBuilding` with stubs (`effectsApplied` kept as saved — finished, ongoing build, damaged by an event, old save without the field — and never re-applied; `rotation` 0-3, old save = 0), QuestSystem (objective progress, choices made, reputation, removed missions), EventSystem (active event without re-applying effects), StudySystem and LoanManager (`nextPaymentAt` in game time, `paymentHistory` dates revived).

**E2E — `tests/save.spec.js`:** plays (study unlock, finished pump → mission done, an ongoing build that fells a tree), saves from the pause screen, reloads the page, picks the profile → "Continuar" and checks buildings/meshes/grid, the build finishing, trees, resources, missions, studies, `gameTime` and no tutorial — plus a building disabled by an event (`effectsApplied: false` survives; removing it after the load subtracts nothing), the save size (< 30 KB, no resource history), every building swapping to its own `.glb` after the load with the ongoing build keeping the model's construction scale, and the timed autosave; also "Novo jogo" (confirm, save deleted, tutorial) and a corrupt save (friendly alert, new game). Desktop only.

**E2E — `tests/building-panel.spec.js`:** selection ring/preview marker/placement overlay above the block top, default rotation facing the camera (preview included) + rotate buttons + rotation surviving save/load, the residents line of a residential zone (building and finished), and the energy guide replacing the first "Energia Insuficiente" alert (once per profile). Desktop only.

**Unit — `tests/unit/world.test.js`:** terrain (hills < 10%, none isolated; start area ≥ 80% buildable; the `terrain` floor never above a voxel block — `GridManager.getTerrainFloorHeight`; voxel/water geometry covers each whole cell with no gap and only the visible sides, none too dark), wind (strong-wind threshold, `windVector` direction) and the quiz review (`StudySystem.getWrongAnswers`).

It also has `todo prédio visível pode ser construído` (desktop only): places every visible building type with unlimited budget/queue — it caught 9 object-sized buildings and the missing `ResourceManager.addWaterConsumption`.

**E2E — `tests/smoke.spec.js`:** boot → new game → place a building → save/load → help/category → study → game over, run as `desktop` and `mobile` (Pixel 5) on chromium. `tutorial congela o jogo e guia a construção da prefeitura` walks the real tutorial (frozen clock, locked buildings, free city hall, skippable parts), checks the animated portraits (Cláudia's `.aportrait` on the first page, Márcia's with every layer from `assets/characters/marcia/`, then Secretário Paulo's page, Cláudia `happy` on the last page) and that every step's character has a `PORTRAIT_MANIFEST` entry. Locally, run E2E with `--workers=1` (CI does): parallel Babylon instances time out on slower machines. It fails on **any** `pageerror`, `console.error`, HTTP ≥ 400 or failed request, so a deleted asset or a leftover `console.error` breaks it. `net::ERR_ABORTED` is ignored (Chromium aborts media range requests). `playwright.config.js` starts the server itself via `npm start` (`reuseExistingServer`).

## Architecture

### Tech Stack

- **No build step** — pure HTML/CSS/JavaScript loaded directly by browser
- **Babylon.js** loaded from CDN, pinned to a version in the URL (`cdn.babylonjs.com/v9.31.2/...`) — bump all 4 tags together and run the full E2E suite (9.31 stopped accepting a disposed/null scene in `new TransformNode`)
- **Python HTTP server** for local development (`python -m http.server 3000`)

### Entry Points

- `index.html` — root HTML; imports all CSS and JS via `<script>` tags
- `js/main.js` — game boot: initializes `GameManager`, wires loading screen, manages screen transitions and BGM

### Key Configuration Files

- `js/config/GameConstants.js` — single source of config, loaded first: `GAME_CONFIG` (initial resources, grid size, autosave/event intervals), `FEATURE_FLAGS`, `CAMERA`, `BUILDINGS` (mesh scale/height), `UI.PANEL_PRIORITIES`, `VALIDATION`. Every constant there is read somewhere — don't add unused ones, and don't put fallback copies of these values in consumers (they used to drift: 30000 vs 40000 initial budget).
- `FEATURE_FLAGS` hides buildings (`HIDDEN_BUILDINGS`: power pole, thermal/coal/nuclear plants), categories (`HIDDEN_CATEGORIES`: `infrastructure` — sidewalk/plaza; the roads live in the visible `roads` category, "Asfalto") and UI features (`rentalButton`) in release.

### Assets

- `Sounds/BGM/` — music (Google Lyria 3) and jingles; `Sounds/SFX/{Player,Environment,RSE}/` — effects/ambiences (ElevenLabs SFX v2), `name_N.mp3` = variations. **Every file is listed in `js/data/audioManifest.js`** (`SOUND_MANIFEST[key] = { kind, files, volume, gap }`, `SOUND_ALIASES` for old/shared names) and has its prompt/model/chosen version in `Sounds/_prompts.json`. Mastering: music -16 LUFS / -1.5 dBTP, MP3 128k; UI/actions -16 LUFS mono 96k, ambiences -22 stereo. `tests/unit/audio.test.js` fails on a missing file, an orphan file in `Sounds/`, a file without prompt or any `'sfx_…'/'bgm_…'/'amb_…'/'voc_…'/'jingle_…'` literal in `js/` that isn't in the manifest.
- `models/buildings/` — building `.glb`s (`kenney/<kit>/` = Kenney City Kits, CC0, each with its `License.txt` and `Textures/colormap.png`; `blender/` = our own models, generated by Python scripts in `blender/_src/`)

### Building models (GLB)

- **Table = style guide, pure data**: `js/data/buildingModels.js` → `BUILDING_MODELS[id] = { file, tris, scale?, rotationY?, yOffset?, tint? }` (`file` relative to `models/buildings/`). 15 Kenney (house, apartment, restaurant, office_building, bank, shopping_center, hotel, school, fire_station, police_station, research_center, tech_center, factory, port, water_tower) and the **own Blender models** (`blender/<id>.glb`, see the table): water_pump, water_tank (Reservatório, redone 10/2026 — the old `Water Tank.glb` was deleted), water_well, water_treatment_plant (ETA), rain_garden, floating_garden, monitoring_station, water_quality_monitor, treatment_plant (ETE), filter_station, hydroelectric_plant, solar_farm, wind_farm, city_hall, museum, park, monument, hospital, university, water_research_center, linear_park, green_roof, green_wall, plus the hidden power_pole, thermal_plant, coal_plant, nuclear_plant. Zones are **not** procedural anymore: each grows through 4 Kenney lots (see "Zones that grow" below). Still procedural: roads (auto-fit pieces, see "Roads"), sidewalk/plaza, erosion_control.
- **Own models (Blender, `models/buildings/blender/`)**: each `<id>.glb` is generated by `_src/<id>.py` with the shared helpers in `_src/lib.py` (boxes, cylinders, pipes, gable/hip roofs, open tanks, windows, trees, a wind rotor). Regenerate one: `"C:\Program Files\Blender Foundation\Blender 4.5lender.exe" -b --factory-startup --python models/buildings/blender/_src/<id>.py`; all: `.../_src/gerar_todos.py` (prints id → tris/KB — copy `tris` into the table). Conventions: 1 cell = 2 units (model the base as `size × 2`), **front toward Blender -Y** and the right side (+X) finished too (those are the two faces the camera sees; `lib.exportar` turns it 180° so it lands on the game's -Z like Kenney), flat colors only (Principled BSDF base color from `lib.PALETA`, no textures/UVs — the loader turns each material color into vertex color), flat shading, light bevel on main volumes. Palette: turquoise/blue = water, green = environment, yellow = energy. Pedagogical: the piece shows what it does (ETA with flocculation → settling → sand filters → treated-water tank with water color changing per stage; filter station with a cut-away column of filter layers; dam with spillway and penstocks). **Moving parts**: nodes named `pas_N` (rotor, spins on the hub axis — `L.rotor`) or `gira_N` (spins upright on Blender Z — `L.animar(pecas, 'gira_1', pivo)`) stay out of the merged mesh: `extractBuildingModelData` returns them in `animated`, `createBuildingModelTemplate` makes them children of the template (pivot in place, axis in `metadata.spinAxis`), `template.clone()` copies them per building (`mesh.animatedParts`, `collectAnimatedParts`) and `BuildingSystem.updateAnimatedParts` (game time, stops in the pause/obra/efficiency 0; rotors follow the real wind) spins them and keeps their material = the parent's. Exported names come out as `gira_1.001` — matched by prefix (`BuildingSystem.ANIMATED_NODE`).
- **Fit is automatic** from the bounding box: base on the ground, centered, longest footprint side = `BUILDING_MODEL_FILL` (0.9) × `size` cells, height capped at `BUILDING_MODEL_MAX_HEIGHT` × that side. Don't hand-tune per model unless needed (`scale`/`rotationY`/`yOffset`). Kenney façades (and our Blender models) already face -Z (toward the isometric camera).
- **Budget ≤ 1,500 triangles per model**; `tests/unit/models.test.js` parses every `.glb`, checks `tris`, textures, CC0 `License.txt`, that water/treatment/power buildings use **only** own models (never a kit file), that own models live in `blender/` with their generator `_src/<id>.py`, have no textures and are ≤ 150 KB, and that no unused Kenney/Blender `.glb` is left in the repo (`ZONE_LOTS` pieces count as used; each zone piece is also ≤ 1,500 tris).
- **Loader** (`building/BuildingModels.js`): each file is fetched **once** (`fetch` + `BABYLON.LoadAssetContainerAsync`, cached promise per file) and turned into a hidden template per type (`modelTemplates`, geometry baked, StandardMaterial with the colormap; material colors become vertex colors). Each building is `template.clone()` (shared geometry, one mesh, own material with `metadata.perBuilding`) with `metadata.fromModel = true`. **Never dispose a template.**
- **Procedural is the fallback**: `createStandardizedBuildingMesh` asks `createBuildingModelMesh` first; while the file loads (or if it fails — only `console.warn`, never `console.error`) the building gets the procedural mesh, and when the model is ready `replaceBuildingMesh(old, new)` swaps it for every building of that type, carrying metadata, base height, construction scale/material, shadow caster/ground shadow/terrain connection, label, icons, selection and children. **Placement preview and construction use the model too**: `startPreviewMode` → `createBuildingModelPreviewMesh` (template clone, own translucent material with `metadata.preview`, shared texture, `isPickable = false`; choosing the building already requests the `.glb`) and `upgradePreviewToModel` swaps a procedural ghost when the file arrives; `disposePreviewMesh` frees the ghost's material, never the texture. Preview is positioned like the final building (`applyStandardizedPositioning` + `getBuildingAreaTerrainHeight`). During the build a model grows bottom-up (`getConstructionScaling`: full footprint, height 15% → 100%, no spin); procedural keeps the old uniform 0.3 → 1 with spin. `removeBuilding` mid-build also clears the progress bar/plate/particles.
- **Zones that grow (residential/commercial/industrial × light/balanced/heavy)**: pure data in `js/data/zoneLots.js` — `ZONE_LOTS[zoneId] = { ground: 'grass'|'paved'|'concrete', stages: [4 lists of pieces] }`, piece `{ file, x, z, rot?, scale?, w?, d?, h? }`: `file` = Kenney `.glb` (relative to `models/buildings/`) or `'prop:<name>'` (procedural construction props in `ZONE_PROPS`: stake, cone, dirt, bricks, pipes, foundation, scaffold, digger, crane; `w/d/h` stretch foundation/scaffold), `x/z` = piece center in **cells** from the lot corner (0..size; camera sees -Z and +X, so tall things go to the back: big z, small x), `rot` = quarter turns like `building.rotation` (0 = façade -Z, 1 = -X, 3 = +X), 1 model unit = `ZONE_LOT_MODEL_SCALE` (0.65) cells. Stages: 0 área livre (dirt, stakes, zone-color border) → 1 início (foundations, first building, machines) → 2 desenvolvimento (half built, scaffolds) → 3 completa. `ZONE_GROWTH` = stage durations (game ms), `effectScale` [0.25, 0.5, 0.75, 1] and stage names.
- **`building/ZoneGrowth.js`** (BuildingSystem partial): the zone mesh is the **lot slab** (`createZoneLotMesh` from `createStandardizedBuildingMesh`: base at y = 0, own ground-color material, zone-color border child, `metadata.fromModel/zoneLot`), so the standard construction site (`underConstruction`) works unchanged; `completeConstruction` → `onZoneConstructionComplete` (stage 0). Pieces are **`createInstance`s** of hidden per-file templates (`zonePieceTemplates`, Kenney files go through `loadBuildingModelFile`; **never dispose a template**), parented to the slab (they rotate/scale/dispose with it) with `metadata.buildingId` (picking works on any piece). `refreshZoneLot` keeps unchanged pieces, disposes removed ones and grows new ones bottom-up. Growth: `updateZoneGrowth` (from `BuildingSystem.update`, by `simNow()`) × `computeZoneGrowthRate` (satisfaction 0.5×–1.5×, energy shortage down to 0.25×, water shortage = stops); `forceZoneStage(id, stage)` for debug/tests. Effects scale with the stage: `getEffectivePopulationCapacity` (used by `ResourceManager.updatePopulationCapacity` and the population panel), `getEffectiveJobCapacity`, and income inside `applyBuildingEffects` via `getZoneIncomeScale` (`setZoneStage` = remove with the old `zoneAppliedScale`, change, add). Save: `zoneStage`/`zoneProgress` in `serializeBuilding`; `restoreZoneState` (old saves without it: finished zone starts at 0 with `zoneAppliedScale = 1`, since their totals had full income). Info panel: `UIManager.generateZoneStageStats` ("Fase: …" + progress bar `#zone-stage-bar-<id>` + "⏱️ Próxima fase em ~N s" `#zone-stage-eta-<id>` with the reason — stopped without water, slower without energy/with unhappy residents, faster when satisfied — from `describeZoneGrowth`/`getZoneTimeToNextStage`, real time ÷ `timeScale`; all updated live by `updateZoneStagePanel`). Stages last 20/30/40 s of game time at rate 1 (they were 50/65/80 and players found it too slow). Tests: `tests/unit/zones.test.js` (data: 4 stages per zone, files exist, every piece inside the lot by the `.glb` bounding box; rate, time → stage, effects, save) and `tests/zones.spec.js` (site → stage 0 → advancing `gameTime` → stages with instances, pause freezes, pick on a piece selects, panel, save/load keeps the stage, removal keeps templates).
- **Zone growth rate, water and evolving**: rate = satisfaction (0.5×–1.5×) × `getZoneEfficiency` (= `building.efficiency` from `BuildingEfficiency.js`, which already counts city energy — never multiply energy again; floor 0.25×), water shortage = 0. `ResourceManager.hasWaterShortage` = production < consumption+waste **and** reserve < 10 s of it (`getWaterBalance`, all L/min; it used to compare the reserve with consumption × 10 = 10 *minutes* and stopped zones with water to spare); the panel says how many L/min are missing (`describeZoneWaterShortage`). Jobs and income scale with stage × efficiency, housing only with the stage. **Evolve** (`ZONE_EVOLUTION` in `zoneLots.js`, `getZoneEvolution`/`evolveZone`): at stage 3 the panel shows "⬆️ Evoluir para <peso>" (light → balanced → heavy, cost = cost difference, disabled with the reason if no money/space); the zone swaps type and restarts at the **lowest stage of the new weight where population, jobs and income don't drop** (progress 0), effects removed/re-added, new lot mesh (`replaceZoneLotMesh`); a 3 × 3 heavy looks for free cells around (`findZoneEvolutionAnchor`, may shift the corner). Save needs nothing new (`type` + `zoneStage`). Unit `tests/unit/zones.test.js`, E2E `tests/zones-evolve.spec.js`.
- E2E: `tests/models.spec.js` (swap, selection, shared geometry, removal keeps the template, restore, `.glb` route aborted → procedural with no error, and preview/obra using the model: ghost not pickable, own material disposed on exit, same position as the build, red when invalid). `npm run screenshots` waits for pending models (`hasPendingBuildingModels()`).
- **AI images (own, generated)**: `assets/images/` — `tutorial/` (story backgrounds behind the book), `lessons/` (figures inside lesson text), `studies/` (`data/building-studies.json` pages), `gameover/`; `assets/characters/<id>/` — animated portraits. **Every prompt is in `assets/images/_prompts.json`** (file → scene prompt, aspect, size, model, shared `style`): new screens/lessons/characters get new images following it (scene first, then `style`; always "no text, no letters, no watermark"; 16:9 medium, WebP ≤ 1280 px backgrounds / ≤ 960 px figures; characters by editing the base with `input_references`). No stock-photo URLs (Unsplash/Pexels/DiceBear/Wikimedia) anymore.
- `data/building-studies.json` — educational content for buildings (used by StudySystem)

## Key Patterns

- **Partial class files (mixin)**: big classes are split across files with `mixin(Class, { methodA() {...}, ... })` (defined in `GameUtils.js`). Methods land on the prototype exactly like class methods, so callers keep using `this.method()`. Partial files go right after their class in `index.html`. `mixin` **throws on a name collision** — on purpose: a duplicated method name used to silently replace the other. Find a method with `grep -rn "    methodName(" js/` — it may live in a partial.
- **Singleton pattern**: `GameManager`, `SaveSystem` — accessed via module-level `let` variables in `main.js`.
- **System communication**: all systems receive a `gameManager` reference at construction and call back through it rather than importing each other directly.
- **Game data lives in `js/data/`**: `buildings.js` (`BUILDING_TYPES`, 63 buildings; `size` = square side in cells; `tier` 1-5, `group` = section in the build menu, `techRequires` = tech tree, see below) and `missions.js` (`MISSIONS`, 7 missions — `final_01` "Cidade Guardiã" has `victory: true` → `GameOverSystem.showVictory()`, "Continuar jogando" = free play; `ACHIEVEMENTS` = name/icon of each `rewards.achievement`), plain global objects keyed by id. `BuildingSystem.initializeBuildingTypes()` / `QuestSystem.initializeQuests()` register them with `structuredClone` — objectives hold mutable progress (`current`), so never register the shared object directly. Keep them pure data (no functions, no `Date.now()`): relative times go as a duration (`timeWindowMs`) and are resolved in `addQuest()`. Balancing a building or mission = edit `js/data/`, not the systems. **Mission order comes from `prerequisites`** (`checkUnlockConditions` starts every mission whose prerequisites are done; a mission without them starts at boot); `rewards.recommendStudy` only points to a study (the study is the only unlock path); `startEvent: { type, durationMs }` starts/extends an event when the mission starts (Crise Hídrica → drought). `build` goals count finished buildings only; `sustained` counts game seconds (`simNow` deltas), not calls. `data/building-studies.json` holds the educational text shown in StudySystem.
- **Tutorial characters (`TutorialSystem.CHARACTERS`)**: Pesquisadora Cláudia (main guide), **Pescador José** (artisanal fisherman, lives off the river: riparian forest, erosion, bioindicators, interface tour) and **Pesquisadora Márcia** (water quality/sanitation field researcher who collects river samples and analyzes them; khaki vest, binoculars, turquoise hair band — Cláudia is the environmental researcher with turquoise shirt and notebook: sewage and dissolved oxygen, floating gardens, cause and effect, tips). People, not animals: no "Croac/Glub" or first-person fish talk; fish and frogs appear only as river animals/bioindicators. **Portraits are animated AI illustrations** (`js/ui/AnimatedPortrait.js`, no 3D): `CHARACTERS[key].id` → `assets/characters/<id>/portrait.webp` (base, 640 px) + cut-out layers `eyes`, `mouth-a`, `mouth-o`, `worried`, `happy` placed by `PORTRAIT_MANIFEST` (`js/data/portraits.js`: `[x, y, w, h]` per layer, `face` square for small circles), each with a feathered radial mask. Breathe/sway in CSS, random blink 3–6 s (skipped while an expression is on), mouth moves with read-aloud (`setupReadAloud` emits `readaloud` events on `document` — `start`/`word` (boundary)/`pause`/`end`; a portrait reacts only if the button is inside its `speechScope`; without boundary events it flaps on a timer) and briefly on each new page (`talk(ms)`). Entrance hop + greeting balloon (`hello`) when a new speaker appears in story mode. Expression per step: `step.expression` or `TutorialSystem.expressionFor` (guides only — `run === 'guide'` — get `worried` on water shortage/critical pollution; quick lessons and the book never look at the city state; `happy` on 🎉/🏆). Story on desktop = bust in a frame; coach/mobile = `face` crop in a circle. One instance per character is reused (`TutorialSystem.portraits`); the lesson book creates its own and destroys them on close; game over shows Cláudia `worried`. `step.character` is the table key; the shown name is `TutorialSystem.displayName()`.
- **Mobile/desktop branching**: `UIManager.isMobile = window.innerWidth <= 768` set at construction and on resize. Many methods early-return with `if (this.isMobile) return` or `if (!this.isMobile) return`.
- **Cooldown system**: `UIManager.cooldownManager` prevents double-triggers. Use `this.isOnCooldown('key')` / `this.setCooldown('key', ms)` when adding new click handlers.
- **Build menu = modal (`ui/BuildMenuUI.js`, `css/build-menu.css`)**: `selectCategory()` fills `#building-items` (moved once into `#build-modal-grid` by `setupBuildModal`) grouped by the building's `group`, and opens `#build-modal`; clicking the open category (or ✕/Esc/backdrop) closes it. One click on a card = `showBuildInfo(id)` (3D preview, effects from the fields `applyBuildingEffects` reads, tech requirements, "abre caminho para"); `#build-info-construct` is always visible at the bottom and says Construir / Estudar para liberar / Tecnologia bloqueada / Falta R$ (`updateBuildInfoButton`, refreshed with the cards); double click on a free card builds at once. Construir → `constructFromBuildModal` (closes the modal, keeps the category marked so a tutorial `enter` doesn't reopen it) → `selectBuildingType` → `enterBuildMode` (desktop and mobile; the old mobile details panel is unused). Not a popup: doesn't pause. Mobile: full screen, info replaces the cards (← Voltar), `body.build-modal-open` hides the floating toggles. Tutorial build targets: `#build-info-construct:not([hidden])` → card → category. Categories: water, treatment, nature, science, public, power, roads, residential, commercial, industrial. **3D preview (`ui/BuildPreview.js`)**: own small Babylon engine on `#build-preview-canvas`, created on first use and kept (render loop only while visible), reusing `BuildingSystem.prototype` loaders with a minimal context like the intro; zones show the last `ZONE_LOTS` stage; no model → the big icon.
- **Camera input mapping** (SimCityCameraControls): left-click drag = pan (tracked at `document` level so dragging off-canvas works); right/middle drag = rotate; scroll wheel = zoom; WASD/arrows = keyboard pan; Q/E = keyboard rotate; R = reset. **Pan is relative to the view** (`moveRelativeToView(right, forward)`: forward on the ground = (-cos α, -sin α), right = (-sin α, cos α), the CompassUI basis) for keys, drag and screen edges, scaled by zoom (`zoomPanScale`); keys typed in inputs are ignored. Covered by `tests/ui-fixes.spec.js`.
- **Mouse drag threshold**: `pendingDrag`/`mouseHasMoved` in SimCityCameraControls prevents micro-movements during clicks from triggering camera pan. Mirrors touch's `touchMoveThreshold`/`touchHasMoved`.
- **Building rotation**: `building.rotation` = quarter turns 0-3 (saved; old saves = 0, `BuildingSystem.normalizeRotation`), mesh `rotation.y = rotation × π/2` around the area center (size > 1 is square, occupancy unchanged). Placement picks the quarter whose façade (-Z) faces the camera (`getDefaultBuildingRotation`: θ = -α - π/2), and the preview ghost follows it every frame (`syncPreviewRotation`). Never reset `mesh.rotation` to zero: obra/completion/`removeConstructionVisuals` use `applyBuildingRotation(building)` (skipped while the "girar" animation runs, `building.rotateAnimation`); the ground shadow turns too. The info panel has "Girar para a esquerda/direita" (`rotateBuilding(id, ±1)`, not for `roadType`). Selection ring and placement overlay sit on the block top (`getBuildingAreaTerrainHeight` / `getTerrainBlockHeight`), never at y = 0 or an elevation formula.
- **Building selection (dual path)**: Desktop uses `scene.pick()` + `metadata.buildingId` in `GameManager.handleBuildingSelection()`. Mobile uses `scene.pick()` + `metadata.buildingId` in UIManager's `touchend` handler. Both rely on `mesh.metadata.buildingId` set by `BuildingSystem.placeBuilding()`. Both pick through `GameManager.pickBuildingFirst(x, y)` (buildings first, then anything), so completion plates/labels in front don't steal the click. Placement, preview and terrain info use `GameManager.pickTerrainCell(x, y)`: it hits what is drawn — the voxel chunks (`metadata.terrain`; top, bevel and sides — the hit point steps back along the normal so a hill's side gives the hill's cell), the water chunks (`water_*`) and the `terrain` floor.
- **Mesh metadata**: Every building mesh gets `metadata.buildingId` in `BuildingSystem.placeBuilding()`. `replaceBuildingMesh()` moves metadata (and everything else tied to the mesh) to the new mesh. This metadata is the primary way buildings are identified on click/tap.
- **Canvas must remain 100% viewport**: Do not resize `#game-canvas` based on HUD panel dimensions — HUD panels are designed as overlays. Changing canvas size breaks Babylon.js rendering and layout.
- **hud-right visibility (desktop)**: Hidden by default (`display: none`). Shown via `showHudRight()` when building/terrain info is displayed, hidden via `hideHudRight()` when panels close.
- **hud-right visibility (mobile)**: Uses `transform: translateX(100%)` to hide off-screen and `.active` class to slide in. Mobile CSS must override `display: none` from base CSS or the panel stays invisible regardless of transform.
- **Panel show/hide must use centralized methods**: Always call `showHudRight()`/`hideHudRight()` instead of manually toggling `.hud-right` display or classes. Methods like `showMissionPanel()` must go through these to work on both platforms.
- **Sound (`AudioManager` + `utils/audio/SoundDirector.js`)**: play by manifest key — `AudioManager.playSound(key, vol, { ifQuiet, pan })` (variation without repeating the last, per-key `gap`; no effects during the menu intro), `playJingle` (ducks the music ~3 s), `playMusic(key)` (2 s crossfade, same key = no-op), `setAmbientLayers({key: level})`, `playLoop/stopLoop`. Short files are fetched after boot and decoded on the 1st gesture (Web Audio, autoplay); music and ambiences stream (HTMLAudio, loop by crossfade) — never preload them. Volumes music/effects/ambient + mute in `localStorage.guardiao_agua_audio`, edited in the pause screen block `#pp-sound` (built by `setupSoundPanel`). Pause: music 35 %, ambiences silent; hidden tab: all silent.
- **Music per context**: `showScreen()` → `AudioManager.onScreen(id)`: menu/profile = `bgm_menu`; `MenuIntro.play()` → `onIntroStart` (`bgm_intro`, 22 s, synced with the shots; reduced motion = menu) and `reveal()`/"Pular" → `onIntroDone` (crossfade to the menu). In game the director (every 1 s) picks: game over (silence + `jingle_game_over`) > `bgm_gameplay_alert` (water ≤ 15 %/< 2 min, pollution > 80, energy < 50 % with some generation; enters at once) > rain/storm (`weatherEffects.profile`) > night (`getDayNightState`) > thriving (satisfaction ≥ 75, pop ≥ 200 and +3 % in 2 min) > day (2-track playlist; start tutorial = day). Stays `director.minDwellMs` (60 s) on a track. Ambiences: city day/night, river, rain/storm/wind/snow/hot sun/fog from the weather profile, traffic with ≥ `CityLifeSystem.MIN_ROADS`. Hooks: `onLightning` (WeatherEffects), `onGameOver`, `onMissionComplete`, `onStudyUnlock`, `onEventStart/End`, `onSpeaker` (tutorial portrait: voice only when the speaker changes). Tests read `currentMusicKey`, `director.contextKey`, `getAmbientKeys()` (`tests/audio.spec.js`); loading a save plays nothing (`restoreBuilding` is silent, energy/population baselines reset).
- **Game over overlay**: `GameOverSystem` detects defeat conditions (water depleted, pollution critical) and shows a fullscreen educational dialog via `#gameover-container`. CSS lives in `css/tutorial.css`; the `.tutorial-*` classes there are used **only** by game over now (the tutorial uses `.tut-*`).
- **Start tutorial freezes the game**: `startNewGame()` sets `gameState = 'tutorial'` — `update()` then only refreshes the HUD; nothing simulates, no autosave, Space/visibility don't pause. `TutorialSystem.complete()` is the only thing that sets `'playing'`. There is **no starter city**: the city hall is built by the player in a mandatory step.
- **Tutorial steps** (`createTutorialSteps()`): after a short hello page and the city hall, a step asks *aprender agora* / *durante o jogo*; the lessons are the `intro` steps with `chapter: 1..6`. Finishing a chapter's last page in the start tutorial marks it done (`LessonProgress`). "Durante o jogo" (or "Pular aulas") sets `lessonsDeferred`, and `QuestSystem.completeQuest` → `tutorialSystem.onMissionCompleted()` opens the next unfinished chapter 4 s later **in the lesson book** (`uiManager.openLessonBook`). The 📚 HUD button (`#btn-lessons`) opens the **lessons hub** (`openLessonsHub`): one card per `LESSON_CHAPTERS` entry (`js/data/lessons.js`, same keys as the steps' `chapter`), done/next status, and a book that turns pages; its last page marks the lesson done. Chapter content stays in the tutorial steps. `startTopic(type)` runs a short coach lesson (`TutorialSystem.TOPICS`, `run: 'topic'`) from the "🎓 Aprender sobre…" button of each resource panel; any `run` other than `'tutorial'` behaves as a lesson ("Fechar aula", returns to `'playing'`). Coach steps with `advanceOnClick: true` advance when the player clicks the spotlighted target (the click reaches the game first) — the missions group uses it. Steps can override button text with `nextLabel`/`skipLabel`. Fields: `group` (`intro` default, `cityhall`, `missions`, `interface`, `end`) and `mode` (`story` default = fullscreen, `coach` = game visible + card + spotlight). "Pular" jumps to the next group; groups without an entry in `TutorialSystem.SKIP_LABELS` are mandatory. Coach steps take `targets` (selectors or `{selector, text, scrollIn}`): the **first one on screen** gets the spotlight and its `text` becomes the hint, re-evaluated every 250 ms — that's how one step guides desktop (category → item) and mobile (🏗️ → item → Construir) without branching. `waitFor: '<buildingId>'` locks "Próximo" until it exists; `enter(gm)` runs on every render of the step (also on "Anterior").
- **Tutorial building hooks**: `BuildingSystem.placeBuilding` calls `tutorialSystem.onBuildingPlaced()` (refunds the cost — city hall is free — and completes construction instantly, since the loop is frozen). `UIManager.selectBuildingType` refuses anything but `tutorialSystem.allowedBuilding` while the tutorial is active.
- **Building placement feedback**: Clicking a disabled (can't afford) building button shows a warning notification with a clickable link to the FAQ budget section (`UIManager.showBudgetInsufficientNotification()`). After placing a building that causes energy deficit, `BuildingSystem.showEnergyShortageNotification()` warns about insufficient power (30s cooldown). **Central alerts never cover reading screens**: `UIManager.showCentralAlert` (energy, low water, no money) checks `isReadingOverlayOpen()` (`#lessons-hub`, `#lesson-book`, `#study-book-overlay`, `#tutorial-container` — story or coach); then the alert waits in `deferredAlerts` (one per title) and `flushDeferredAlerts()` (every 200 ms from `UIManager.update`) shows it when they close, skipping it if `options.stillRelevant()` says it's stale (energy: `isEnergyShortProjected()`, counting ongoing builds). `options.whenBusy: 'toast'` (the budget alert, a reply to a click) shows a non-blocking notification instead. `tests/effects.spec.js` covers it.

## Gotchas

- **Two kinds of pause — both freeze `gameTime`, the clock of constructions and missions** (`BuildingSystem.simNow()`, `QuestSystem.simNow()`; never `Date.now()` for game logic, or things "jump" after a pause): (1) the pause/profile screen — `pauseGame()` (Space, tab hidden, click on the player name) shows `#pause-overlay`, which is the player panel (data, stats, ❓ help, save, menu; the HUD ❓ was removed); (2) the **soft pause** — `holdPause(reason)`/`releasePause(reason)` stop the simulation without changing `gameState` or opening a menu. `UIManager.syncPopupPause()` (every 200 ms from `update()`) holds it while any informational popup is **visible** (list in `isInfoPopupOpen()`); **when you add a popup, add its selector there**. `isSimulationRunning()` tells both apart from `'playing'`.
- **Player profile**: the menu lists saved profiles (`.profile-card` starts the game with it); "Novo Jogador" opens `#profile-screen` (name, age, state from `BRAZIL_STATES`, city from the IBGE API with free-text fallback, geocoded by Open-Meteo). `GameManager.applyPlayerProfile()` applies `DIFFICULTY_BY_AGE` (event chance + initial budget) and starts the weather. Write `{nome}` in tutorial/mission texts and render them through `PlayerProfile.personalize()` (escapes the name — it goes into innerHTML). Profiles without coordinates retry geocoding on every weather refresh. **Every external fetch (IBGE, geocoding, forecast) aborts after `WEATHER.FETCH_TIMEOUT_MS` (5 s)**: Open-Meteo sometimes holds the connection ~60 s, which froze the profile form on "Procurando sua cidade"; now the game starts without coordinates and the weather refresh geocodes later.
- **Weather**: the clock HUD item (`#clock-weather`) shows temperature + animated CSS scene; click anywhere on it → `#weather-modal` (the clock text only updates `textContent` of fixed spans and has `pointer-events: none` — rewriting its innerHTML every 100 ms swallowed clicks) (now + 5-day forecast + a water tip). `GameManager.applyWeather(current)` → `WeatherEffects`, whose light tweak runs **inside** `updateDayNightLighting()` (the day/night cycle rewrites lights every second). Clouds/rain must stay below the camera (~18-25 high) to be seen. Wind uses Open-Meteo `wind_gusts_10m`/`wind_direction_10m` (`windDir` = where it comes **from**; `WeatherEffects.windVector` gives where it blows); `profile.windy` (≥ 30 km/h or gusts ≥ 50) turns on the wind-streak particles.
- **Voxel terrain and water (`GridManager.createVoxelTerrainBlocks`/`createWaterBodies`)**: blocks fill the **whole cell** (they used to be 98%: through the gaps you saw the darker floor, and black lines near hills). The block look comes from a darker bevel on the top edge (`TERRAIN_BEVEL`, vertex colors). Built without Babylon by `buildTerrainGeometry`/`buildWaterGeometry` (only visible sides: neighbour lower, water or map edge; sides facing away from the sun are brightened in the vertex colors, top colors × `TERRAIN_BRIGHTNESS` because vertex color comes after the StandardMaterial light clamp) and merged per `TERRAIN_CHUNK`×`TERRAIN_CHUNK` cells: 16 land + ≤ 16 water meshes, one material each (was ~1,600 boxes with a material each). Water: one `ShaderMaterial` for every chunk (`waterCell` vertex attribute = cell x/z, depth, top flag; `time` from `performance.now()`), or `waterSimpleMat` (vertex color/alpha) on low quality — `setWaterAnimated`. The old decorations (only on `dirt`, which the map never generates) and the line grid were removed.
- **Terrain floor (`terrain` mesh)**: the ground under the voxel blocks, now seen only under the water. `applyElevationToTerrain` puts each vertex `GridManager.TERRAIN_FLOOR_GAP` (0.15) below the lowest block top it touches (`getTerrainFloorHeight`, water = 0) with `setVerticesData` + `refreshBoundingInfo`. It used to be elevation × 2 via `updateVerticesData` on a non-updatable buffer: the GPU drew it flat but picking used the CPU copy, up to 1.4 above grass tops — the "terrain above the blocks" near hills.
- **Terrain & start area**: hills are ~5% of the map (`determineTerrainType` thresholds + `removeIsolatedHills`). `GridManager.findStartArea()` picks the 8×8 window with ≥ 80% buildable land (freest first, then most central) → `gridManager.startArea`; `startNewGame` points the camera there and `TreeSystem` keeps it clear of trees.
- **Trees (`TreeSystem`, values in `TREES`)**: each standing tree adds `POLLUTION_REDUCTION`/min and `ResourceManager.greenBonus` (satisfaction); `placeBuilding` calls `fellTreesInArea` (pollution jumps, bonus drops, warning toast) and the placement preview turns **orange** when the spot has trees. `ResourceManager.reset()` zeroes the reduction, so `startNewGame` calls `treeSystem.applyEffects({ fresh: true })` after it. Trees are instances of hidden templates (`isVisible = false`): dispose instances, never the templates while trees exist.
- **Planted trees (`tree_sapling`, "Muda de Árvore", Tratamento, unlocked by default)**: `building/TreeGrowth.js` (BuildingSystem partial, zone pattern) grows them through 4 `treeStages` in `buildings.js` by game time — stage 1 only consumes water (and stops growing without water), stages 2-4 only cut pollution; `applyBuildingEffects` delegates to `applyPlantedTreeEffects` (exact amounts kept in `building.treeApplied`), `treeStage`/`treeProgress` saved. Mesh = pit with mulch + wooden stake; the tree is an instance of `TreeSystem.getPlantedTemplate()` (lime crown) with `metadata.buildingId`. Clicking a native tree → `TreeSystem.selectAt` (ring + `#native-tree-info`, `ui/TreeInfoUI.js`). Can't plant on a native tree. Tests: `tests/unit/trees.test.js`, `tests/trees.spec.js`.
- **Esc**: never closes an interactive (coach) tutorial — guides, quick lessons, start-tutorial coach parts: the `GameManager` window-capture listener swallows it while `tutorialSystem.mode === 'coach'` (only cancelling build mode), so neither the card nor the panels it highlights close. Otherwise it cancels build mode / closes panels first; with nothing open (`GameManager.isIdleForEscPause()`) it opens the pause/profile screen, and in the pause it resumes. The listener is on `window` in **capture** so it decides with the state from before the other Esc handlers close things. Esc also closes the right panel (`.hud-right`: resource, terrain, missions, selection — `UIManager.isHudRightVisible()` counts as "not idle").
- **Leaving mid-game** (`main.js`): F5/Ctrl+R and the browser Back button ask in a `gameConfirm` ("Salvar e sair" autosaves); closing the tab only gets the native `beforeunload` prompt (text fixed by the browser). In Playwright, accept the `beforeunload` dialog before `page.goto` mid-game.
- **Save/load (`SaveSystem` + `GameManager.getSaveData/loadGame`)**: one save per profile in `guardiao_agua_save_<profileId>`, envelope `{ format, version: SaveSystem.VERSION, profileId, savedAt, kind, summary, game }`; bump `VERSION` when `game` changes incompatibly (other versions are refused as `incompatible`, broken JSON/missing fields as `corrupt` → friendly alert + new game). Clicking a profile with a save asks **Continuar / Novo jogo** (`gameChoice`, SweetAlert deny button); "Novo jogo" confirms and deletes the save. **A lost game can't be continued**: `SaveSystem.isLostGame(game)` (water < `LOST_WATER_RATIO` 5% of capacity or pollution ≥ `LOST_POLLUTION` 90) → friendly alert, save deleted, new game; `autoSave` skips such states and `triggerGameOver` deletes the save. Saving needs `gm.tutorialDone` (set by `TutorialSystem.complete()` for the start tutorial, which also autosaves; true after a load) — the start tutorial is never saved. Autosave: every `autoSaveInterval` while playing, on study unlock (`StudySystem.saveProgress`), on "Salvar e sair"/menu and on `beforeunload`. **Resources are restored as saved and effects are NOT re-applied**: `ResourceManager` totals (production, pollution sources/reduction, income/expenses, storage, power, `buildingConsumption`) already include buildings, trees and active events; `BuildingSystem.restoreBuilding` recreates mesh/grid/connections/obra visuals without cost, tree felling, effects, sounds, notifications or tutorial hooks, and `TreeSystem.loadData` only fixes `appliedReduction`/`greenBonus`. Order in `loadGame`: resources → trees (saved cells; the map is random per game) → buildings. Ongoing builds keep `constructionStartTime` (gameTime) and finish normally. `serializeBuilding` saves `effectsApplied` (a finished building disabled by `EventSystem.disableRandomBuilding` has no effects in the totals; old saves without the field fall back to "finished = applied"). `ResourceManager.history` is not saved (nothing reads it; it was most of the save). Terrain is deterministic (position-seeded noise), so it isn't saved. When you add state that matters to a system, add it to its `getSaveData`/`loadData` and to `tests/unit/save.test.js`.
- **Building effects apply once, when the construction finishes** (`completeConstruction`), never at placement. `applyBuildingEffects` keeps `building.effectsApplied`, so a repeated add/remove is ignored (removing an unfinished build subtracts nothing). Changing something the effects depend on (`efficiency`, `isRented`) = remove with the old value, change it, add again. The "Energia Insuficiente" alert at placement uses the projected consumption. `tests/effects.spec.js` checks it.
- **Economy (`ResourceManager`)**: `budget.income = BASE_INCOME + taxes + budget.buildingIncome` — building/zone/rental income goes through `addIncome`/`removeIncome` into `buildingIncome` (it used to be overwritten every second, so no building earned anything). `satisfactionBonus` sums into `population.buildingSatisfaction`; satisfaction gets `buildingSatisfactionEffect` = 15 × (1 − e^(−sum/40)). Satisfaction = sum of `getSatisfactionFactors()` (the 😊 panel lists the same factors).
